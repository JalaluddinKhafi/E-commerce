# تازه‌مارکت · Freshshop

فروشگاه با **Spring Boot، React و Redux**: نمایش و جستجوی محصولات، ثبت‌نام و ورود، سبد خرید پایدار، سفارش با پرداخت هنگام تحویل، و پنل مدیریت محصولات و سفارش‌ها. رابط فارسی، راست‌به‌چپ و سازگار با موبایل است.

## اجرا در Windows / PowerShell

نیازمندی‌ها: JDK 17، Maven 3.6.3 یا بالاتر، Node.js 22.12 یا بالاتر و npm. [نیازمندی‌های Spring Boot](https://docs.spring.io/spring-boot/3.5/system-requirements.html) و [Vite](https://vite.dev/guide/).

ترمینال اول، از پوشهٔ پروژه:

```powershell
cd backend
mvn spring-boot:run
```

ترمینال دوم، از پوشهٔ پروژه:

```powershell
cd frontend
npm ci
npm run dev
```

فروشگاه: <http://127.0.0.1:5173> — وضعیت API: <http://127.0.0.1:8080/api/health>.
در اولین اجرا چهار محصول نمونه ساخته می‌شود. حساب مشتری را از «ثبت‌نام» بسازید.
دیتابیس پیش‌فرض H2 به‌صورت فایل در `backend/data/` ذخیره می‌شود؛ این پوشه را برای نگهداری اطلاعات حفظ کنید. از یک دیتابیس فایل با دو اجرای هم‌زمان استفاده نکنید.

### حساب مدیر

پیش از اجرای بک‌اند، در همان ترمینال متغیرهای زیر را با مقادیر خود تنظیم کنید:

```powershell
$env:ADMIN_EMAIL = 'your-email@example.com'
$env:ADMIN_PASSWORD = 'choose-a-unique-password-here'
$env:JWT_SECRET = 'replace-with-a-random-secret-of-at-least-32-bytes'
cd backend
mvn spring-boot:run
```

رمز مدیر حداقل ۱۲ نویسه و حداکثر ۷۲ بایت UTF-8 باشد. کلید امضا حداقل ۳۲ بایت باشد. هیچ حساب مدیر با رمز پیش‌فرض ساخته نمی‌شود. حساب مدیر فقط وقتی ایمیل جدید باشد ساخته می‌شود؛ اجرای دوباره رمز مدیر موجود را تغییر نمی‌دهد و حساب مشتری موجود را به مدیر تبدیل نمی‌کند.

با ایمیل و رمز تعیین‌شده وارد شوید؛ لینک «مدیریت» در منو ظاهر می‌شود. متغیرها فقط در همان ترمینال برقرارند. فایل `.env` فقط توسط Docker Compose خوانده می‌شود؛ اجرای مستقیم Maven آن را خودکار نمی‌خواند.

## امکانات پیاده‌شده

- کاتالوگ، جزئیات محصول، جستجو، دسته‌بندی و مرتب‌سازی بر اساس قیمت.
- جستجو و صفحه‌بندی در دیتابیس، مرتب‌سازی پایدار و لینک قابل اشتراک برای فیلترها.
- علاقه‌مندی‌های محلی در مرورگر.
- ثبت‌نام، ورود با BCrypt، توکن JWT یک‌ساعته و کنترل نقش در سرور.
- سبد خرید اختصاصی هر حساب؛ افزودن، کم‌وزیادکردن و حذف کالا.
- محاسبهٔ مبلغ در سرور، بررسی موجودی و ثبت سفارش تراکنشی.
- قفل موجودی برای جلوگیری از فروش هم‌زمان بیش از موجودی.
- جلوگیری از ثبت تکراری سفارش با کلید درخواست UUID.
- سابقهٔ سفارش با قیمت و مشخصات کالا در زمان خرید.
- مدیریت محصول، موجودی، قیمت و پنهان‌کردن محصول.
- مدیریت مراحل سفارش و برگشت موجودی هنگام لغو مجاز.
- ویرایش نام حساب، تغییر رمز با تأیید رمز فعلی، و خروج از همهٔ نشست‌ها.
- لغو سفارش توسط خریدار پیش از شروع آماده‌سازی، با تأیید و برگشت موجودی.

مبالغ به سنت دالر امریکا ذخیره می‌شوند. ارسال ۵ دالر است؛ سفارش ۵۰ دالر و بیشتر ارسال رایگان دارد. حداکثر تعداد هر کالا در سبد ۹۹ است. کالاهای سبد رزرو نمی‌شوند؛ موجودی هنگام ثبت سفارش دوباره بررسی می‌شود. تغییر قیمت نسبت به مبلغ تأییدشده، ثبت سفارش را متوقف می‌کند تا خریدار مبلغ جدید را ببیند.

توکن فقط در حافظهٔ برنامه نگهداری می‌شود. بازخوانی صفحه یا پایان اعتبار توکن نیازمند ورود دوباره است؛ سبد و سفارش‌ها در دیتابیس باقی می‌مانند. خروج عادی، نسخهٔ توکن را از مرورگر پاک می‌کند. از «حساب من» می‌توانید نام را ویرایش کنید، رمز را تغییر دهید یا همهٔ نشست‌ها را ببندید؛ تغییر رمز و خروج از همهٔ نشست‌ها، توکن‌های قبلی را در سرور نامعتبر می‌کند. تغییر رمز نیازمند رمز فعلی است؛ بازیابی رمز فراموش‌شده هنوز فعال نیست.

خریدار فقط سفارش «ثبت شده» را می‌تواند لغو کند. پس از آغاز آماده‌سازی، درخواست لغو باید از طریق فروشگاه پیگیری شود؛ مدیر تا پیش از ارسال می‌تواند سفارش را لغو کند. لغو تکراری موجودی را دوباره افزایش نمی‌دهد.

## ساخت و تست

از ریشهٔ پروژه:

```powershell
mvn -B -f backend/pom.xml verify
cd frontend
npm ci
npm run format:check
npm run build
npx playwright install chromium
npm run test:e2e
```

تست‌های مرورگر بک‌اند و Vite را با دیتابیس حافظه‌ای و حساب مدیر آزمایشی خودشان اجرا و سپس متوقف می‌کنند؛ پورت‌های ۸۰۸۰ و ۵۱۷۳ باید آزاد باشند. ابتدا دستور `mvn verify` را اجرا کنید تا JAR به‌روز باشد. داده‌ها و رمز ثابت داخل تست‌ها فقط برای محیط آزمایشی هستند.

اگر دانلود Chromium ممکن نبود ولی نسخه‌ای روی دستگاه نصب است:

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = 'C:\path\to\chrome.exe'
npm run test:e2e
```

GitHub Actions نیز ساخت، تست بک‌اند، بررسی قالب‌بندی و تست مرورگر را اجرا می‌کند. نتیجهٔ اجرای محلی در [گزارش بررسی](docs/VERIFICATION.md) آمده است.

## اجرا با Docker و PostgreSQL

```powershell
Copy-Item .env.example .env
# مقادیر واقعی و تصادفی را در .env تنظیم کنید.
docker compose up --build
```

آدرس: <http://127.0.0.1:8088>. Nginx فایل‌های React و مسیرهای API را از یک مبدأ ارائه می‌کند. PostgreSQL در volume پایدار `shop_database` نگهداری می‌شود. برای توقف از `docker compose down` استفاده کنید؛ افزودن `-v` اطلاعات دیتابیس را پاک می‌کند.

پیکربندی Compose اعتبارسنجی شده، اما اجرای کانتینرها و اتصال واقعی PostgreSQL در محیط توسعهٔ این تغییر تأیید نشده است، چون Docker daemon فعال نبود. برای انتشار عمومی، دامنه، HTTPS و تنظیمات عملیاتی میزبان باید جداگانه فراهم شود. هیچ سرویسی در اینترنت منتشر نشده است.

## ساختار

```text
backend/              Spring Boot 3.5، Spring Security، JPA، H2 / PostgreSQL
frontend/             React 19، Redux Toolkit، Vite، CSS و Playwright
docs/                 قرارداد API و نتایج بررسی
compose.yaml          PostgreSQL + backend + Nginx / React
*.html, css/, js/     قالب اولیه برای مراجعه و حفظ تاریخچه
images/, webfonts/    دارایی‌های قالب اولیه
php/                  فرم تماس قدیمی؛ خارج از برنامهٔ جدید
```

برنامهٔ جدید از JPA و یک دیتابیس SQL برای کاربران، موجودی، سبد و سفارش استفاده می‌کند. MongoDB و Tailwind در این نسخه به‌کار نرفته‌اند؛ توضیح اولیهٔ مخزن که این فناوری‌ها را پیاده‌شده معرفی می‌کرد، با ساختار واقعی جایگزین شده است. تصاویر موجود از همین مخزن استفاده شده‌اند؛ پیش از انتشار تجاری، مجوز دارایی‌های قالب اولیه بررسی شود.

## محدودهٔ نسخه

این نسخه مسیر کامل خرید با **پرداخت هنگام تحویل** را اجرا می‌کند. اتصال درگاه پرداخت واقعی، بارگذاری تصویر، بازیابی رمز، تأیید ایمیل، مالیات و اتصال شرکت ارسال هنوز پیاده نشده‌اند. پنل مدیر از تصاویر موجود انتخاب می‌کند؛ آپلود فایل ندارد. کالاهای نمونه برای نمایش برنامه‌اند.

قالب قدیمی با بازکردن `index.html` نمایش داده می‌شود، اما فروشگاه متصل در `frontend/` است. فرم تماس قدیمی به PHP و سرویس ایمیل، همچنین `CONTACT_TO_EMAIL` و `CONTACT_FROM_EMAIL` نیاز دارد؛ در برنامهٔ React فعال نیست و ارسال واقعی ایمیل تست نشده است.

برای جزئیات مسیرها و قوانین سفارش، [قرارداد API](docs/API.md) را ببینید.

تاریخ‌های نویسنده و ثبت‌کنندهٔ کل تاریخچه به درخواست مالک در بازهٔ ۷ سپتمبر تا ۲۸ دسمبر ۲۰۲۵ تنظیم شده‌اند. تعداد روزانه به‌صورت متغیر بین ۸ تا ۲۵ است و ۱۰ روز مشخص بدون کامیت می‌ماند. توسعهٔ جدید و بازچینی تاریخچه در ۷ نوامبر ۲۰۲۶ انجام شده؛ این تاریخ‌های تنظیم‌شده، زمان واقعی نوشتن تمام کد نیستند. کامیت‌های کوچک شامل بخش‌های کد موجود و استایل‌های اولیه هم هستند و به معنی همین تعداد قابلیت تازه نیستند. [گزارش بازنویسی و برنامهٔ روزانه](docs/HISTORY.md) را ببینید.
